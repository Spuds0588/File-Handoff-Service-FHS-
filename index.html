Zero-retention relay · Cloudflare Workers + Durable Objects

Hand a file between two systems without writing it to disk.

FHS takes a binary upload, returns a single-use URL, streams the bytes to the receiver exactly once, and keeps no copy. No bucket, no database, no vendor data store to audit.

What it does

Four properties do the work. Everything else is plumbing.

One upload, one download

POST /upload returns a random 122-bit token and a handoff URL. The first GET streams the bytes and burns the token. Every later request gets HTTP 410.

Nothing touches disk

Chunks live in the memory of isolated Durable Objects. FHS never calls R2, KV, D1, or Durable Object storage, so there is no stored copy to retain or expire.

Bounded at both ends

Uploads stream in and are split into 8 MB chunks, one Durable Object each. Downloads pull chunks in order and stream them out, so no single isolate holds the whole file.

A clock, not a queue

The TTL starts when the upload is sealed. If the receiver misses the window the payload is gone and Service A uploads again. There is no retry buffer to clean up.

What it's for

For the gap between two backends that have to exchange a file but should not share storage, credentials, or a provider.

  • NPI and PHI on the move. Claims attachments, lab PDFs, KYC documents, signed agreements passed from a producer system to a consumer system.
  • Replacing shared buckets. No long-lived signed URL, no lifecycle rule to prove, no object left behind by a failed cleanup job.
  • Smaller vendor surface. The relay holds bytes in memory for under a minute, so there is no persistent store to add to a vendor register.
  • Internal tooling. Moving an export or a build artifact between two CI systems without a shared filesystem.

What it is not

FHS is a relay, not storage: not durable, not a queue, not a workflow engine. A payload can disappear before its TTL if the Durable Object is evicted, so treat 410 as “upload it again”. And it does not make you compliant on its own. Retention rules, agreements, and endpoints are decisions about your whole system.

How a handoff works

  1. Upload Service A sends the file to POST /upload. The Worker streams it in and writes 8 MB chunks into separate Durable Objects.
  2. Seal A layout record is written last. That starts the TTL clock and produces the token. The response is the only copy of that token.
  3. Retrieve Service B calls GET /retrieve/:token. The Worker burns the layout record, pulls chunks in order, and streams them to the caller.
  4. Gone The token now answers 410. Chunks that were never read are zeroed when their timer fires, and an evicted Durable Object takes its bytes with it.

Stand it up on your own account

You need a Cloudflare account (the free plan is enough) and Node 20.3 or newer. The Worker is named file-handoff-service; Cloudflare prints its workers.dev URL when the deploy finishes.

Fresh account: open Workers & Pages once before the first deploy. Without a workers.dev subdomain, Wrangler stops with code 10063. The setup script can create one with --subdomain <name> when CLOUDFLARE_API_TOKEN is set; the OAuth login cannot call that API. A new hostname can also reject TLS for up to a minute while its certificate is issued.

Deploy to Cloudflare Deploy from another repo

One click clones this repository into your account, provisions the Durable Object, and deploys the Worker with no required fields. Then gate either side with npx wrangler secret put UPLOAD_SECRET or npx wrangler secret put RETRIEVE_SECRET; neither is required.

Or run the setup script, from the repo you are already in

curl -fsSL https://raw.githubusercontent.com/Spuds0588/File-Handoff-Service-FHS-/main/scripts/setup.mjs -o /tmp/fhs-setup.mjs
node /tmp/fhs-setup.mjs

The script checks FHS out to a temporary directory, deploys it, sets the upload secret outside your repo, verifies a real handoff, and removes the checkout. Your project is left untouched. Add --no-upload-secret to leave uploads open, --config <file> for a filtered profile, or --subdomain <name> to create the first hostname. It probes with the deployment's actual MIME allowlist.

Or use the CLI, from a local clone

1 — Get the code

git clone https://github.com/Spuds0588/File-Handoff-Service-FHS-.git fhs
cd fhs
npm install

This repo is a GitHub template. You can also press Use this template and deploy your own copy.

2 — Log in once

npx wrangler login

On a brand-new account, open Workers & Pages once before deploying. That creates the workers.dev subdomain and avoids code 10063.

3 — Deploy

npx wrangler deploy

No prompts and no bindings to create by hand: the Durable Object binding and the v1 migration already live in wrangler.jsonc.

Need a filtered deployment? Wrangler does not merge configs, so copy the complete profile and run npx wrangler deploy --config deploy/pdf-only.jsonc. npx wrangler dev --config deploy/pdf-only.jsonc tests it locally.

4 — Check it

export FHS=https://file-handoff-service.YOUR-SUBDOMAIN.workers.dev
curl -sS "$FHS/"
curl -sS -X POST --data-binary @report.pdf \
  -H "Content-Type: application/pdf" \
  "$FHS/upload"

The first call returns a JSON descriptor with the live limits. The second returns a token and a handoff URL that works once.

Local tests need no Cloudflare account at all: run npm test.

Shut it down

Deleting the Worker stops requests immediately and drops any payload still held in memory. FHS never persists payloads, so there is no bucket or database to empty. 

npx wrangler delete
# or, for the production profile:
npx wrangler delete --config deploy/simplepdf.jsonc

The same action is in Workers & Pages → select the Worker → Settings → Delete. If Cloudflare reports a leftover Durable Object namespace, remove it under Workers & Pages → Durable Objects and retry. Worker-scoped secrets stop working. Do not delete the account-wide workers.dev subdomain just to remove one Worker; it affects every Worker on the account.

If the setup script generated ~/.fhs/upload-secret, remove that local file too: rm -f ~/.fhs/upload-secret.

Use it

Method Path Purpose
GET / JSON descriptor: version, routes, limits, filters, and auth requirements.
POST /upload The request body is the file. Returns 201 with a token and a handoff URL.
GET /retrieve/:token Streams the file once (200). Any later attempt returns 410.

Producer, Node.js

import { readFile } from "node:fs/promises";

const file = await readFile("report.pdf");
const response = await fetch(`${process.env.FHS}/upload`, {
  method: "POST",
  headers: { "Content-Type": "application/pdf" },
  body: file,
});

const { handoffUrl, expiresInSeconds } = await response.json();
// Send handoffUrl to the consumer over your own trusted channel.

Consumer, Node.js

import { writeFile } from "node:fs/promises";

const response = await fetch(handoffUrl);

if (response.status === 410) {
  throw new Error("handoff expired or already consumed");
}
if (!response.ok) throw new Error(`retrieve failed: ${response.status}`);

await writeFile("report.pdf", Buffer.from(await response.arrayBuffer()));

Both examples use Node 20's global fetch. Any HTTP client works: the retrieve response is a plain 200 whose body is the file, so no SDK is involved.

Retrieved files use Content-Disposition: attachment, so an iframe or embed downloads instead of rendering. To preview, fetch the handoff with any required headers, create a Blob, and use URL.createObjectURL(blob).

Status 409 is internal to the Durable Object layer; the public upload path converts it to 500 and purges. If a retrieval fails after its 200 headers, the client sees a truncated body or network error, not a later 500.

Configuration

Variable Default Notes
TTL_SECONDS 60 5 to 3600. Clock starts when the upload is sealed.
MAX_PAYLOAD_BYTES 26214400 (25 MB) Up to 94371840 (90 MB).
CHUNK_SIZE_BYTES 8388608 (8 MB) 64 KB to 16 MB, one Durable Object per chunk.
ALLOWED_CONTENT_TYPES unset (any) Upload only. Comma-separated declared MIME types; image/* wildcards; blocked uploads get 415; the declared type is echoed on retrieve.
REQUIRE_PDF_MAGIC unset (false) Upload only. When true, a declared PDF must begin with %PDF- before any chunk is stored; otherwise 415.
ALLOWED_UPLOAD_DOMAINS unset (any) Upload-only Origin/Referer hosts; *.example.com; blocked uploads get 403.
ALLOWED_RETRIEVE_DOMAINS unset (any) Retrieve-only Origin/Referer hosts; *.example.com; blocked retrievals get 403.
UPLOAD_SECRET unset When set, uploads require Authorization: Bearer <secret>; retrieval is unaffected.
RETRIEVE_SECRET unset When set, retrievals require Authorization: Bearer <secret>; upload is unaffected.

Set plain values under vars in wrangler.jsonc, then redeploy. For secrets use npx wrangler secret put UPLOAD_SECRET or npx wrangler secret put RETRIEVE_SECRET; never commit them.

What each control constrains

Consumer Constrained by Not constrained by
A page fetching the handoff ALLOWED_*_DOMAINS; a blocked origin gets 403 and no CORS. A User-Agent list; FHS does not check one.
A backend or proxy The token, plus RETRIEVE_SECRET if set; no Origin is sent. Domain allowlists.
A URL pasted into the address bar The token only; browsers cannot attach Authorization. Domain allowlists and RETRIEVE_SECRET.

The sides are independent. Empty or unset means any or no secret, so you can gate uploads, retrievals, both, or neither. Domain checks are browser CORS, not authentication; use the secrets for real authorization. MIME filtering trusts the declared header; REQUIRE_PDF_MAGIC=true adds a five-byte PDF signature check before any chunk is stored.

Questions

What is the File Handoff Service?

FHS is a small Cloudflare Worker plus one Durable Object class that relays a file between two backend systems. Service A uploads it, FHS returns a single-use URL, Service B downloads it once, and the bytes are dropped from volatile memory.

Does FHS store my files?

No. Payloads live only in the memory of isolated Durable Objects. FHS never writes to R2, KV, D1, or Durable Object storage, and it does not log payload contents.

How long does a handoff last?

60 seconds by default, measured from the moment the upload is sealed. The TTL is configurable from 5 seconds to 3600 seconds with TTL_SECONDS.

How large can a file be?

25 MB by default. MAX_PAYLOAD_BYTES can raise it to 90 MB, which stays under the Workers Free and Pro request-body ceiling of 100 MB. Uploads and downloads stream in 8 MB chunks so no single isolate holds the whole file.

Can I restrict who can upload or retrieve a handoff?

Yes, independently. ALLOWED_UPLOAD_DOMAINS and ALLOWED_RETRIEVE_DOMAINS accept hostnames such as app.example.com,*.example.org for browser Origin/Referer checks. Blocked origins return 403. UPLOAD_SECRET and RETRIEVE_SECRET optionally require Authorization: Bearer on their side, independently. ALLOWED_CONTENT_TYPES and MAX_PAYLOAD_BYTES apply to uploads. Domain checks only govern browsers; use the secrets for real authorization.

Why does my first deploy fail with code 10063?

The account has no workers.dev subdomain yet. Open Workers & Pages once in the Cloudflare dashboard to create it, or use the setup script with --subdomain and a CLOUDFLARE_API_TOKEN. Wrangler's OAuth login cannot create the subdomain through the REST API. A new subdomain may also reject TLS for up to a minute while its certificate is issued.

What happens if the receiving service is down?

The payload expires and the handoff URL returns HTTP 410. FHS is a relay, not a queue: re-upload the file when the consumer is ready.

Is FHS HIPAA or GLBA compliant?

FHS is built for zero-retention transit: no durable copy, no payload logging, single use, short TTL. That removes a stored-data surface, but compliance also depends on your agreements, network, endpoints, and legal review. FHS is not a certification.

Can I self-host FHS somewhere other than Cloudflare?

It needs long-lived, addressable in-memory state. Cloudflare Workers with Durable Objects provides that. A stateless function platform or an object-storage-only backend cannot hold the bytes without writing them to disk, which defeats the design.

How do I shut down FHS?

Delete the Worker with npx wrangler delete, or with npx wrangler delete --config deploy/simplepdf.jsonc for that profile. This stops requests and drops in-memory payloads; FHS has no durable payload store. If Cloudflare reports a leftover Durable Object namespace, remove it under Workers & Pages → Durable Objects. The account-wide workers.dev subdomain is separate; do not delete it just to remove one Worker.
